# 和朋友一起记录问题 · 0.4.6

## 一次完整的排障记录

1. 你和朋友都使用 0.4.6。退出正在运行的旧客户端后安装；保留原私网身份，不要退出设备或重建 ZeroTier 网络。
2. 进入房间前，打开菜单「小屋 → 诊断记录窗口」，或按 Ctrl+Shift+D；进房后也可点「诊断记录窗口」按钮。
3. 双方点击「开始记录」。默认关闭，不会偷偷录制。页面/资源约每 3 秒采样，原生视频约每 2 秒产生统计；文件内同时保存原生事件及最近一次原生快照。
4. 用同一段动态画面，先由一人共享 2—3 分钟，再换另一人共享。发现卡顿但共享内容声音正常时，选择新增的「画面卡顿，声音正常」，点击「标记问题」。其他问题使用对应选项。继续运行 20—30 秒，留下恢复过程，不要立刻结束共享。
5. 双方点击「停止并保存到桌面」。等待“已导出”提示，点「打开产物位置」。
6. 把双方桌面的 ZIP 发回来，并说明哪个文件属于分享者、哪个属于观看者，以及测试的大致时间、网络类型和当时现象。不要只发截图或只提供分享者一侧文件。多人房间可能经过成员转发，最好参与测试的每个人都开启记录。

## 文件保存在哪里

- 可直接发送的文件：桌面根目录的「同屏小屋诊断-日期时间_随机标识.zip」。
- 原始记录：桌面「同屏小屋诊断」文件夹中的本次记录目录。
- 文件名、记录行使用 UTC 时间，诊断窗口的事件列表显示本机时间，便于跨设备对齐。
- ZIP 内含概览、会话信息、逐次采样和事件记录；它不会自动上传。

关闭诊断窗口会停止并保存；最小化窗口会继续记录。退出程序也会尝试完成导出。若电脑关机、进程崩溃或被强制结束，已经逐条写入的记录仍在桌面；下次打开窗口可点「打包上次记录」。异常结束的包可能没有 summary.json，不能视为完整结束。

单次最多 2 小时或 20 MiB 原始统计，达到限制自动停止并导出。不会自动删除旧记录；不再需要时可自行删除桌面 ZIP 与对应文件夹。桌面不可写或磁盘满会显示错误，已保存部分仍保留，房间继续工作。

## 能看到什么

保留实际分辨率、帧率、码率、目标设置、语音连接、音量、候选过滤/私网验证、ZeroTier 活动直连和整机/程序 CPU/内存等已有统计。新增「原生视频路径与恢复」区域：

- 对外发送：视频连接自己的 RTCP RTT、ICE 探测 RTT、NACK/PLI/重传缓存计数、发送队列包数/字节数、最老等待时间、累计/最长排队时间、队列满丢弃、取消探测和写入错误。
- 对外接收：原生视频实际读入包数、RTX 修复包、剩余缺包、乱序/重复包、补包/关键帧请求、最近包年龄和转发错误。
- 本机播放：单独标记，关联其上游视频边，避免将本机统计误当成异地网络统计。
- 播放恢复：浏览器完整帧、已解码帧、关键帧、组装时间、冻结和缓冲计数；浏览器未支持的项目保留为空。
- 共享声音：原生音频入口、最后到包时间，以及播放器的音频包数、补偿采样和能量。与房间麦克风语音分开，便于分析“画面卡住但共享声音正常”。

CPU 按整机逻辑处理器容量归一化。程序工作集加总可能包含重复的共享页，不代表实际独占内存；GPU 显存与利用率未采集。

0.3.10 的本机视频桥接显示“本机直通”，对应 queue.pacing=local-direct；跨电脑发送仍显示“网络节奏控制”，对应 network-paced。这是发送调度方式，不表示 ZeroTier 一定已经建立底层直连。旧版没有该字段时保持未知。

## 避免误判

- 语音 RTT/丢包来自浏览器语音连接；原生播放器 RTP 来自本机播放桥接。两者不能直接当作异地原生视频网络的 RTT/丢包。
- 本版重新编译了私网媒体组件，新增数值诊断扩展。发送侧 RTT 是媒体反馈所得，接收侧可提供所选视频传输的 ICE 探测 RTT；接收侧没有可用的 RTCP RTT 时显示“—”，不能用语音 RTT 补位。
- 原生 rtp.markerFrames 只是 RTP 帧尾标记计数，不能当成已组装或已解码帧；完整帧恢复应与浏览器 framesReceived、framesDecoded、keyFramesDecoded、冻结和组装耗时一起看。
- 缺包采用同一流内累计计数差分；packetsLost 可能因迟到/修复而下降。nackRequests 是库统计的包请求计数，nackMessagesSent/nackCount 是反馈报文数，不能混算为丢包率；nackAcks 是发送缓存命中，不证明对端成功收到。
- queue.sentPackets/sentRtpBytes 是交给本机传输层的成功写入，不证明远端收到；discardedPackets 包含队列满、取消探测及关闭，排查阻塞要结合 overflowDrops、writeErrors、pendingPackets 和 oldestQueuedMs。maxQueueResidenceMs 是该连接生命周期的最大值，并非本次采样独有峰值。
- 原生 rtcpFeedbackAgeMs 是最近一次 RTT 更新回调距今的时间，不是所有 RTCP 报文的最长空窗。对外发送端的缺包反馈需结合 RTT/反馈是否已经到达判断。
- 音频收包/能量不能替代实际听感；正常的共享声音也不能保证视频包完整。
- 原生分配预算不是宽带测速。DIRECT 表示当时存在活动直连路径，没有直连证据不等于一定走中继。
- 缺失/过期数据为 null 或“—”，不是零；低帧率也可能来自静态内容、源窗口或设备，不能只凭一个数就断定网速不足。
- samples.jsonl 的 native[] 与 events.jsonl 的 diagnostics 按 scope（network/local-playback）、direction 和 edgeTag 分段；sourceEdgeTag 连接本机播放与上游，startedAtMs/streamTag 帮助识别计数重置。sampleTimestampMs 与 ageMs 用于时间对齐；两台电脑的时钟仍可能有偏差。
- 概览的 FPS 混合了共享与观看角色，不是单一方向的平均表现；判断性能须读取逐次记录。schema 更新为 friendscreen-diagnostics-v2，旧 ZIP 无需转换。

## 隐私

不录屏、不录音，不保存昵称、头像、真实 IP、主机名、Windows 用户名、窗口标题、完整房号、邀请码、口令、SDP、候选地址、网络令牌或密钥。设备、房间、共享和链路 ID 使用单向摘要，以便双方日志匹配。日志仍包含活动时间和设备运行统计，请只发送给你信任的排障人员。

## 0.3.10 观看与预算

导出中的 playbackMode、playbackTargetMs、playbackSupported 分别表示本机观看方式、请求的接收缓冲目标和接口支持情况；它们不是端到端显示延迟。uploadBudget 是用户选择的预算，videoCeiling 是分配后的单路编码上限，声音、重传和封装会占用额外流量。麦克风语音与共享声音仍分开统计。
