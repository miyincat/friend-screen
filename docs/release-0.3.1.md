# 同屏小屋 0.3.1 私网测试版

本次修复针对房间成员刚加入时，两端可能先收到对方的 WebRTC offer 或 ICE 候选、再收到成员加入事件的竞态。旧客户端在 PeerConnection 尚未创建时会丢弃这些信令，连接因而停在 `new`，屏幕与语音媒体都无法启动。

客户端现在按设备 ID 暂存早到信令；收到成员事件并创建 PeerConnection 后按顺序回放。队列有 peer 数量、单 peer 和总条数上限，超限时优先丢弃旧 ICE 候选以保留会话描述；成员离开或退出房间会清除缓存。连接诊断新增信令状态、ICE 连接状态及候选收集状态。overlay 候选校验和媒体发送前的私网路径验证保持不变。

自动化验证：`npm test` 19 项通过，`npm run test:network` 11 项通过；浏览器回归 10 项通过，使用真实 WebRTC PeerConnection 和合成画面/音频，其中一项强制将 offer/ICE 排在 `peer-joined` 之前，验证后来加入的成员仍能连接、接收视频帧和两路音频 RTP。打包程序首次启动和设备 ID 持久化检查 5 项通过，安装包静态一致性检查 27 个文件匹配源码。测试结果保存在 `artifacts/media-regression-2026-11-04/`。

两台真实电脑的 ZeroTier 跨网络媒体、真实麦克风与系统声音仍未在本次运行中验证。新的安装包需要由双方安装后再按跨网络环境复测。屏幕系统声音仍需共享者重新开始共享并在选择器中勾选“共享音频”。

本版独立实现，不包含 Oopz 代码、资源、协议或服务。安装器未签名，安装网络服务与驱动需要 UAC。出现 SmartScreen 提示时应先核对由管理员单独提供的 SHA-256。
