# 同屏小屋 0.3.4 · 清晰度和媒体路径修复测试版

## 本次修改

1. 私网路径检查由单一布尔值改为已验证、待验证、明确拒绝三类。统计记录尚未完整、路径切换、读取失败时暂停音视频并保留房间成员，后续重新校验成功后自动恢复，不因暂缺统计直接关闭连接。明确地址不匹配、非 UDP、relay/srflx 等不符规则仍拒绝。
2. 实际选中候选在统计中标为 peer-reflexive（prflx）时，仅在双端地址精确匹配已认证的 ZeroTier IPv4 且协议为 UDP 时允许；信令候选规则仍只接受指定地址的 UDP host，没有开放普通局域网、公网、STUN 或 TURN。
3. 屏幕由 motion 改为 detail，发送端显式设置 maintain-resolution、缩放比例 1 和既有档位码率/帧率上限。优先保留桌面文字细节，带宽不足时允许降低帧率。没有强行保证 1080p60 或提高最低码率。
4. 指标改为发送 / 接收速率。观看端原先显示的是自己的发送，0 Mbps 不能说明没有收到视频。实际传输画面取编码/解码统计，不再把本机采集尺寸当作真实发送尺寸。诊断显示帧率及编码器报告的带宽/CPU限制。画质参数应用失败不再显示完全成功。
5. 观看别人时禁用自己的共享画质选择器，避免误以为能远程修改朋友的发送画质。

## 更新及复测

双方退出旧客户端，覆盖安装 0.3.4，保留既有昵称、头像与设备身份。不要退出当前设备、删除资料或更改 ZeroTier 网段。重新开房并加入，由分享者选择 1080p30 后开始共享；优先选择实际想分享的窗口，避免把同屏小屋自己的预览一层层共享出去。

观看端关注接收速率及实际传输画面；发送和接收速率不要求相同，静止桌面也不必持续占满码率上限。出现私网验证中时音视频会暂停，成员保留，恢复后自动继续；明确不合规的路径仍会关闭。若仍失败，保存双方完整诊断，特别是实际发送/接收尺寸、帧率、限制原因及路径状态。

## 验证与限制

本机真实 ZeroTier 网卡、真实 WebRTC、1920×1080 合成图像测试中发送和接收均为 1920×1080，发送约 30fps；模拟统计缺失超过 3 秒后不会移除成员，恢复后继续解码；精确私网 prflx 通过、明确公网地址拒绝。详见 test-report-0.3.4.md。

这些是单机回归及注入场景，不证明用户截图一定由统计暂缺或 prflx 引起，也不证明两台不同网络上的清晰度与稳定性已解决。两台实体电脑跨网、真实麦克风/系统声音、6–7台设备10分钟以及干净系统安装仍未验证。

## 回滚与许可

旧版发行目录与桌面安装包保留。退出后可覆盖安装 0.3.3 回滚，但旧版可能再次因统计不足误断开。源码回滚副本保存在 artifacts/rollback-0.3.3。未复制 Oopz 代码、素材、协议或服务。安装器未签名，网络组件安装需要 UAC。
