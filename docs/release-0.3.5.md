# 同屏小屋 0.3.5 · 1080p60 目标与连接稳定性

## 本次修改

1. 默认共享目标改为 1080p60，目标尺寸固定。实际编码/解码尺寸与基于连续帧差的实测帧率会显示在连接诊断中；未达到所选目标时会明确标记。目标设置和实际效果是两件事，受采集源、设备编码性能、网络可用带宽和对端解码能力限制。
2. 将原生 H.264 能力排在视频编码偏好的前面，并保留浏览器支持的其他编码及修复格式作为协商回退。没有修改 SDP 编码参数或声称一定使用硬件编码。当前诊断同时报告实际协商编码器。
3. 主客户端窗口关闭 Electron 后台节流，以便游戏遮住或最小化客户端时，仍能运行房间和路径验证任务。屏幕来源仍要由用户在系统选源器中主动授权。
4. 通过实时 ICE 选中路径进行严格私网校验。当前可验证的私网 UDP 路径不因统计暂缺而中断；若实时路径和统计都不可读，则仍暂停媒体。播放暂停时保留视频对象，避免重新建立播放管线；确实恢复/变更路径时展示不同状态。
5. 连接诊断显示稳定采样窗口下的实际帧率、协商编码、发送/接收码率、路径切换记录，以及可用时的网络预估、累计丢包和冻结统计。
6. 资料组件未加载时显示启动错误并阻止进房，避免页面停留在模糊的连接检查状态。
7. Windows 发行包已构建并通过 29 项包内文件一致性检查；打包版首次设置与身份持久化回归 5 项通过。实际安装、UAC 和 ZeroTier 入网仍未验证。

“流畅优先·允许降清”是用户主动选择的自适应保底，会在带宽受限时降分辨率；“清晰优先·文字细节”可能牺牲帧率。默认“保持目标尺寸”不会把低清流畅误报为1080p目标已达成。

## 复测

双方退出旧版并覆盖安装 0.3.5，不要退出当前设备、删除本机身份或重建/修改 ZeroTier 网络。分享者可先保持默认 1080p60，选实际游戏/应用窗口进行共享；观看端查看接收尺寸和实测帧率。默认上限 1080p60 为 8 Mbps。更高上限不会突破实际链路可用吞吐；拥塞、丢包或中继仍会影响结果。观看端的选择不能远程改变分享者的档位。

连接详情需分别检查双方的实际编码/解码尺寸、帧率、发送/接收速率、路径验证切换和冻结/丢包数据。尤其是观看端的接收速率。若每几秒出现私网重新验证，保存双方完整诊断，连同 ZeroTier peers 中相关设备的状态一并发给管理员；不要改网段、开放公网监听或关闭防火墙。

## 验证边界

单机测试使用当前 Windows x64、Edge、一个真实 ZeroTier 网卡、localhost 信令及隔离身份。H.264 优先的合成全屏运动回归连续 10.06 秒测得 1920×1080，编码 52.31 fps、解码 52.30 fps；这项基准只达到本轮 50 fps 门槛。另一次 Electron 原生窗口采集测试中，1920×1080 测试画布实际采集、编码和解码尺寸为 1918×1080；前台发送 59.59 fps、接收 60.25 fps，最小化阶段发送和接收均约 59.96 fps，恢复后均约 60.03 fps。每阶段持续约 7–10 秒，使用本机 localhost/同机接收端和合成动画。它证明本机采集链路能跑到接近 60 fps，不证明朋友之间的 ZeroTier 跨网效果，也不是实际游戏负载。受限 600 kbps 的编码上限注入样例约 16.4 fps并发生冻结，不代表跨网限速结果。详细记录见 test-report-0.3.5.md、`artifacts/media-quality-0.3.5/` 和 `artifacts/desktop-performance-0.3.5/results.json`。

双实体电脑跨网、真实游戏窗口在前台/遮挡/最小化时的捕获帧率、实际 ZeroTier 直连或中继条件、真实麦克风和系统声音、6–7台设备长时间运行及干净 Windows 安装均须以对应测试报告为准；不能把单机回归说成跨网验收。

未放宽私网规则：信令仅允许已认证 overlay IPv4 UDP host 候选；实际所选路径仍须精确匹配双方认证地址。没有复制 Oopz 代码、素材、协议或私有服务。本版本为未签名测试版，Windows 安装会显示 UAC。
