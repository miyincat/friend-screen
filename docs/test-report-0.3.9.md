# 同屏小屋 0.3.9 验证报告

日期：2026-11-05。测试环境：一台 Windows 11 x64 电脑，Electron 45.2.2、Node 24.21.0、Go 1.27.3；使用已有 ZeroTier IPv4、隔离的合成身份、测试窗口和合成声音。没有替代真实两台异地电脑验收。

## 保持分辨率的恢复对照

同一段移动色块画面、相同 1080p60 目标和 20 Mbps 上限。两侧实际捕获/接收尺寸始终为 1920×1078（Windows 测试窗口的实际捕获区域）。每组有 60 秒持续观察，首末有效播放采样覆盖约 63 秒。

| 指标 | 修复前媒体路径 | 修复后，相同故障条件 | 修复后，正常链路 |
|---|---:|---:|---:|
| 实际分辨率 | 1920×1078 | 1920×1078 | 1920×1078 |
| 播放帧率中位数 | 0.67 FPS | 59.28 FPS | 60.00 FPS |
| 区间实际解码帧率 | 0.79 FPS | 59.17 FPS | 59.98 FPS |
| 接收速率中位数 | 17.28 Mbps | 17.32 Mbps | 17.49 Mbps |
| 本机视频平均排队 | 199.71 ms | 约 0.001 ms | 小于 0.001 ms |
| 本机队列满丢弃/写错 | 0 / 0 | 0 / 0 | 0 / 0 |

故障条件：单向增加 14 ms；每 800 个主视频 RTP 包丢弃一个；每 200 个主视频包额外延迟 80 ms，重合时丢弃优先。声音和 RTX 包不主动丢弃。测试代理只绑定本机私网地址，不解密、不记录媒体内容。两组均无代理队列溢出或写入错误。

修复前使用已交付的 0.3.8 原生二进制及旧 H.264 组帧路径；诊断测试外壳的版本号为 0.3.9，因此旧路径日志的 version 字段不是旧安装器验收。修复后使用本版原生组件和生产共用的 H26xPacketBuffer 设置。

这是同分辨率、相近吞吐量的改善，没有将降清后的帧率计为本表结果。此前高噪声探索画面触发过原有自动降档，其结果只用于定位，不用于声称 1080p 达标。单独取消排队也未恢复帧率；最终同时修正本机交付方式和 H.264 组帧路径。

指标注意：旧路径低帧率时 freezeCount 也可能为 0，不能只凭这个计数判定流畅；本次按真实解码计数、分辨率、时间差和帧率一起验收。排队等待不是端到端显示延迟。

证据：artifacts/stutter-0.3.9/comparison.json、before-1080/results.json、fixed-1080/results.json 与 live-window.png、after-1080/results.json。scripts/verify-stutter.mjs 自动检查原始 ZIP：分辨率不降、实际解码速度、队列、共享声音、故障条件一致和改进幅度。

## 其他回归

- Go 聚焦测试通过：本机直通仍支持真实 NACK/RTX 修复；网络连接保留节奏控制和 BWE；本机连接不启动带宽探测；ICE 重启保留连接并拒绝旧答案；私网绑定限制保持。
- Node：服务 19 项、私网/路径 43 项、诊断 9 项通过。
- 四个隔离客户端的原生回归通过：同房、二层转发、下游持续解码、转发成员退出重排、普通成员接替共享、房主离开关闭房间、原观看者新开房。
- 合成麦克风 0/100/200%、个人收听音量和静音、闭麦释放音轨通过；合成共享声音经采集和转发后音频波形非零。不是物理麦克风或实际听感测试。
- 实际原生 UDP 套接字只绑定 ZeroTier IPv4；没有通配或物理网卡监听。
- 监视窗口、问题标记、停止写入、关闭/退出导出与脱敏检查通过。截图已检查。

四客户端证据：artifacts/private-native-0.3.9/results.json、01-relayed-view.png。只持续观察了 20 秒多客户端媒体，不是 7 台物理电脑的长时验收。
